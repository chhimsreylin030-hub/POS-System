System Architecture

3-Tier Distributed Architecture

Modular decoupling ensures high availability, data consistency, and seamless local development.

1. Client Layer

Flutter Web / Desktop / Mobile
  • Responsive layouts from 360px mobile to 4K desktop
  • Real-time state with FoodDeliveryState
  • Zero RenderFlex overflow with auto-wrapping
  • Hosted locally on port 8085

2. Service API Tier

Dart REST API Server (Port 8081)
  • bin/server.dart standalone HTTP daemon
  • CORS-enabled REST endpoints for Auth, Menu, Orders
  • Auto-detects credentials across all machines
  • Resilient auto-reconnect recovery loop

3. Database Tier

MySQL 8.0 (Port 3306)
  • Strictly isolated database: pos_db
  • smartfood_db remains 100% untouched
  • ACID-compliant transactions for payments & orders
  • Automatic connection pooling & schema migrations

Privacy & Lifecycle

Customer Privacy & Logout Data Wipe

Guests can freely browse the catalog, but upon logout all user-specific data vanishes cleanly from client memory.

🔒 Authenticated Session

  • Saved Addresses & Notes: User can view, add, and dynamically edit delivery locations.
  • Password Visibility: Interactive show/hide eye toggle during password typing.
  • Custom Invoices: pos_db.transactions filtered strictly by customer ID.
  • Loyalty Tier: Silver, Gold, or VIP status with active discount point balance.

💨 Instant Logout Vanishing

  • Cart Wipe: cartItems.clear() and cartMerchant = null executed immediately.
  • Order History Erasure: Past invoices reset to empty list so next user cannot view records.
  • Active Tracking Reset: Active live delivery tracker dismissed instantly.
  • Zero Storage Leakage: Sensitive customer tokens and profile objects cleared from memory.

🛡️ Multi-User Independence

User A and User B share zero local state. Logging out of Account A completely purges local storage before Account B signs in, adhering to GDPR-compliant transient session handling.

Order Pipeline

Real-Time Kitchen & Delivery Pipeline

Step-by-step synchronization between customer order placement, merchant kitchen acceptance, and driver dispatch.

1

Customer Places Order (Status: PENDING)

Customer selects items, chooses Payment Method (Cash on Delivery or Card), and confirms checkout. Order inserted into pos_db.transactions.

2

Merchant Audio/Visual Notification Alert

Merchant Web Portal receives new ticket via 3-second auto-poll. Prominent pink alert banner appears with order total, customer notes, and action button.

3

Kitchen Accepts & Dispatches Driver (Status: DELIVERING)

Merchant clicks "Agree & Accept Dish". Order status updates in MySQL. Assigned driver (Sokha Chea) is dispatched. Customer tracker advances in real time.

4

Order Delivered & Completed (Status: COMPLETED)

Merchant or Driver marks ticket complete. Revenue added to merchant sales ledger. Customer tracking advances to "Delivered • Enjoy Meal".

Database Architecture

MySQL Relational Schema (pos_db)

Normalized relational structure designed for performance, multi-store scalability, and clean audit trails.

🏢 merchant_accounts

Corporate Parent Entity

  • id (PK, auto_increment)
  • account_name & email (Unique)
  • company_reg_number
  • password (Hashed or verified)

🏪 merchants

Physical Restaurant Outlets

  • id (PK)
  • account_id (FK → merchant_accounts)
  • name & khmer_name
  • cuisine, rating, delivery_fee

🍲 products

Menu Dishes & Inventory

  • id (PK)
  • merchant_id (FK → merchants)
  • name & selling_price
  • category, image_url

👤 customers

User Registry & Loyalty

  • id (PK)
  • phone (Unique) & email
  • password & default_address
  • membership_tier, loyalty_points

🧾 transactions

Orders & Invoices

  • id (PK)
  • invoice_number (Unique)
  • merchant_id & customer_id
  • grand_total_usd, status

📦 transaction_items

Line Item Breakdown

  • id (PK)
  • transaction_id (FK)
  • product_id (FK)
  • quantity, line_total
Quality & Responsive Engineering

Responsive UI & Accessibility Upgrades

Engineered to eliminate rendering exceptions and deliver fluid experiences across phones, tablets, and desktops.

📱 Dynamic Layouts & Zero Overflow

  • Auto-Wrapping Toolbars: Fixed Row widgets converted to Wrap and LayoutBuilder.
  • Adaptive Header: Under 900px, top bar collapses into horizontal smooth-scroll with hamburger navigation drawer.
  • Auto-Sizing Menu Grid: Replaced static column grids with maxCrossAxisExtent: 320 for perfect scaling.
  • Ellipsis Constraints: Text clipping prevents RenderFlex subpixel overflow on ultra-narrow viewports.

🔑 Security & Convenience Enhancements

  • Password Hide/Unhide: Interactive eye icon for secure typing on both Customer and Merchant authentication forms.
  • Dynamic Address Editor: Customers can add, update, and manage delivery addresses on the fly.
  • Conflict-Free Port Binding: Web runner configured to port 8085 to prevent conflicts with Java/Tomcat (port 8080).
  • Self-Healing DB Launcher: run_app.bat automatically verifies and starts MySQL service if stopped.
