SmartFood Delivery & POS Platform

Multi-Tenant System Architecture, Database Design & Process Flow
Environment: pos_db (MySQL 8.0)
Date: October 2026 • Production Architecture

1. Executive Summary & Core Platform Components

The SmartFood Platform is an enterprise multi-tenant food delivery and merchant point-of-sale ecosystem. It supports simultaneous operations across four user roles: Customers, Merchants, Drivers, and Platform Administrators, backed by an ACID-compliant MySQL database.

📱 Customer Mobile App

Features restaurant discovery, coupon system, interactive address editor, password eye toggle, and real-time order status tracking.

💻 Merchant Web Portal

Isolated merchant controller for 10 corporate restaurant groups. Includes instant kitchen audio/visual alert banner, ticket workflow, and dish CRUD.

🛡️ Corporate Admin & Driver

High-level platform oversight, store revenue analytics, customer CRM, driver dispatch, and audit trails.

2. 3-Tier Distributed Architecture

The platform separates presentation, API orchestration, and persistence into three decoupled tiers:

  • Client Tier (Flutter Multi-Platform): Serves Web, Desktop, and Mobile. Responsive design dynamically adapts from small smartphone screens (360px) to ultra-wide displays without RenderFlex overflows. Hosted on local port 8085.
  • Service API Tier (Dart REST Server • Port 8081): bin/server.dart handles JSON endpoints, multi-store transactions, dynamic host resolution, and automatic connection retries.
  • Database Tier (MySQL 8.0 • Port 3306): Dedicated strictly to pos_db. All production data and constraints reside here while external databases remain completely untouched.

4. Customer Privacy & Instant Logout Data Vanishing

To comply with stringent data privacy standards and support multi-user shared devices:

  • Guest Browsing: Unauthenticated users can explore menus and store ratings, but cannot view invoices, loyalty points, or place orders without authenticating.
  • Private Session: Customer login retrieves their dedicated address history and specific orders filtered by customer ID.
  • Instant Logout Vanishing: When the customer clicks "Log Out", the client state immediately executes:
    • cartItems.clear() and cartMerchant = null: Shopping cart emptied.
    • customerOrders = []: Past invoice records purged from view.
    • activeTrackingOrder = null: Active live delivery tracking dismissed.
    • Customer address and identity tokens completely erased from client memory.

5. End-to-End Kitchen Order Pipeline

1
Order Placement (Status: PENDING): Customer completes checkout. Order inserted into pos_db.transactions with unique invoice number.
2
Real-Time Kitchen Alert Banner: The merchant web portal auto-polls every 3 seconds. When a new ticket arrives, an animated pink notification banner alerts kitchen staff.
3
Acceptance & Driver Dispatch (Status: DELIVERING): Kitchen clicks "Agree & Accept Dish". Transaction status advances to DELIVERING and driver Sokha Chea is assigned.
4
Completion & Revenue Settlement (Status: COMPLETED): Driver or merchant marks delivery completed. Financial ledger updates and customer tracker marks order finished.

6. MySQL Relational Schema (`pos_db`)

  • merchant_accounts: id (PK), account_name, email (UNIQUE), phone, company_reg_number, password
  • merchants: id (PK), account_id (FK), name, cuisine, rating, delivery_fee_usd, total_sales_usd
  • products: id (PK), merchant_id (FK), name, selling_price, category, image_url
  • customers: id (PK), name, phone (UNIQUE), email, password, default_address, loyalty_points
  • transactions: id (PK), invoice_number (UNIQUE), merchant_id (FK), customer_id (FK), grand_total_usd, status
  • transaction_items: id (PK), transaction_id (FK), product_id (FK), quantity, line_total

7. Recent UX & Stability Improvements

  • Interactive Password Visibility: Eye toggle allows users and merchants to show/hide passwords during typing.
  • Dynamic Delivery Address Editor: Customers can add, edit, or customize delivery addresses directly from the mobile UI.
  • Port 8085 Conflict Resolution: Configured web runner to port 8085 to avoid conflicts with background Java/Tomcat instances on 8080.
  • Zero-Overflow Responsive Layouts: Replaced rigid Row widgets with SingleChildScrollView, LayoutBuilder, and Wrap, preventing RenderFlex overflow exceptions on narrow viewports.
